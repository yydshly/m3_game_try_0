# 02_TASK_BREAKDOWN - 任务拆分

## 总体执行策略

不要一次性大改所有东西。按 6 个阶段推进，每一阶段都必须能运行、能截图、能回退。

---

## P0：建立视觉基线与资源目录

目标：让项目有明确的视觉参考和资源路径。

动作：

1. 新建目录：
   - `docs/ui-reference/`
   - `src/assets/ui/`

2. 把参考图放入：
   - `docs/ui-reference/desktop-target.png`
   - `docs/ui-reference/mobile-target.png`

3. 把 SVG 资源放入：
   - `src/assets/ui/`

4. 不改业务逻辑。

验收：

- 项目能启动
- 资源路径存在
- git diff 清晰

---

## P1：CSS 设计系统

目标：先统一视觉语言，不急着改布局。

动作：

1. 在 `src/styles.css` 顶部增加 CSS variables：
   - 色彩
   - 圆角
   - 阴影
   - 间距
   - 字体层级

2. 重构基础卡片、按钮、meter、panel 样式。

3. 所有旧样式继续兼容。

验收：

- 页面不崩
- 颜色明显变暖
- 卡片更游戏化
- 按钮有 hover / active

---

## P2：主界面布局重构

目标：桌面端形成“顶部 HUD + 左操作 + 中地图 + 右角色 + 底故事区”。

动作：

1. 修改 `renderApp()` 输出结构。
2. 增加容器 class：
   - `.game-shell`
   - `.game-hud`
   - `.game-board`
   - `.game-left`
   - `.game-main`
   - `.game-right`
   - `.game-story`

3. 将现有模块重新排序：
   - 顶部：Hero + HUD
   - 左侧：今日目标 / 操作按钮 / AI 管家
   - 中央：小镇地图
   - 右侧：居民详情
   - 底部：动态 / 关系 / 日报

验收：

- 第一眼不再像后台
- 地图居中且最大
- 操作与角色详情在两侧

---

## P3：小镇地图游戏化

目标：地图成为主视觉。

动作：

1. 强化 `.town-stage`
2. 为地点节点增加游戏牌样式。
3. 居民按钮改为角色气泡。
4. 加草地、路径、光斑、河流/道路感的 CSS 装饰。
5. 最新动态气泡改为 `📌 最新动态`。

验收：

- 五个地点清晰
- 居民存在感明显
- selected/hover 有反馈
- 看起来像小镇地图

---

## P4：角色面板与操作区游戏化

目标：右侧像角色卡，左侧像游戏操作。

动作：

1. 居民详情改为角色档案卡。
2. Agent Needs 改为徽章/小进度条。
3. 按钮改为大号游戏按钮：
   - 推进阶段
   - AI 管家安排
   - 结束今天
   - 自动推进
4. AI 状态错误文案友好化。

验收：

- 选中居民像角色
- 用户明确知道下一步点哪里
- AI 管家像游戏内助手

---

## P5：故事区改造

目标：底部有游戏叙事感。

动作：

1. 小镇动态做成时间线卡片。
2. 日报做成小报纸/手账。
3. 邻里关系做成情绪条。
4. 事件类型图标化：
   - action: 🏃
   - social: 💬
   - system: 🔔
   - report: 📰

验收：

- 小镇动态像故事流
- 日报有仪式感
- 关系模块不再像数据表

---

## P6：移动端适配与验收

目标：手机能用，体验不拥挤。

动作：

1. `@media (max-width: 900px)`：
   - 单列布局
   - 地图在前
   - 操作按钮变成双列或纵列
   - 角色卡不溢出

2. 跑验证脚本。

验收：

```bash
npm run check
npm run agent-check
npm run smoke
npm run render-check
npm run dev
```

访问：

```text
http://127.0.0.1:4173
```

最终截图应明显接近参考图的气质。
