MiniMax-M3 在 V1 中承担了四个角色：规划者（安排居民任务）、叙事导演（生成小镇事件）、广播员（生成广播文案）、记忆引用者（将记忆注入 prompt）。

🔍 开发过程中的反思

做对了什么

  • 先验证 AI 驱动闭环，不先做复杂美术
  • 轻量 Web 原型快速试错，没有一上来上游戏引擎
  • 玩家选择进入记忆链路，小镇真的在"记得"
  • 用测试脚本保护关键体验，不用每次手动回归
  • API fallback 设计，无 Key 也能运行
  • 点击居民后的观察反馈让世界更可交互

暴露了什么问题

  • render.js 逐渐变重，UI 和游戏状态混合
  • 状态边界不够清晰，uiState / state / isAnimating 纠缠
  • 缺少统一演出状态机，travel→task→feedback 靠隐式约定
  • 事件/任务/记忆/对话是轻量拼接，不是系统化机制
  • 缺少真正游戏主循环，玩家目标不清晰
  • 缺少居民关系成长系统和故事结构

🚫 为什么 V1 到这里就该停止？

继续堆 TTS 连续剧、背景音乐、自由对话、更多地图、更多居民，
并不会自动让它变成游戏。
当前最大瓶颈已经从技术实现转移到游戏设计。

真正的问题不是"还缺什么功能"，而是：玩家每天为什么回来？居民为什么值得关心？ 这些不是技术问题，是设计问题。V1 代码有原型技术债，在有技术债的代码上继续开发，会持续遭遇架构摩擦。

现在停止不是放弃，而是把一次成功的技术探索沉淀下来，避免把原型拖成不可维护的半成品。

📐 下一次 AI 游戏开发前，需要先设计什么？

问题为什么重要
玩家是谁？决定世界如何对待玩家
玩家每天为什么回来？没有日活动力，游戏就没有意义
一天的核心目标是什么？有目标才有结构，有结构才有体验曲线
居民为什么值得关心？如果居民只是任务机器，就没有情感价值
居民关系如何推进？关系不推进，就没有成长感
玩家选择如何产生长期后果？没有后果的选择是空气
小镇记忆如何影响未来事件？记忆不产生后果，玩家就不会认真对待
AI 事件导演如何避免随机散乱？AI 生成自由度过高会让世界失去连贯性
哪些内容由 AI 生成，哪些由规则控制？AI 是工具，不是上帝
核心原则：先设计，再开发。先主循环，再功能堆叠。先规则边界，再 AI 生成。

🌿 未来如果重做，它可以讲什么故事？

玩家来到一个逐渐失去活力的小镇。这里有居民，有建筑，有每天的日常，有选择，有记忆。 居民不是任务 NPC，而是带着记忆、遗憾、习惯和愿望生活的人。 玩家每天做出小选择，这些选择不会立刻改变世界，但会慢慢改变居民关系、小镇氛围和未来事件。

AI 像一个温柔的事件导演，观察居民状态，记住玩家选择，在合适的时间安排冲突、广播、问候和日常事件。

最终目标不是通关，而是让玩家感觉：这个小镇真的在生活，而自己参与过它的变化。
